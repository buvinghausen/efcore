# Temporal Entity Splitting and Per-Store-Object Facets — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SQL Server temporal facets resolvable per store object so an entity can map a temporal principal table alongside explicitly non-temporal entity-splitting fragments, and make relational key/FK constraint names expressible per store object.

**Architecture:** Two independent workstreams on the same thesis. **Workstream A** (`EFCore.SqlServer`) adds an `IsTemporal` facet to `EntityTypeMappingFragment` — modeled move-for-move on `UseSqlOutputClause`, the one existing per-fragment SQL Server facet — then teaches validation, the annotation provider, design-time codegen, and the query pipeline to resolve temporality per table rather than per entity type. **Workstream B** (`EFCore.Relational`) adds a new per-store-object override metadata family for key and foreign-key constraint names, patterned on `RelationalPropertyOverrides` but with FK overrides carrying a composite `(dependentStoreObject, principalStoreObject)` identity.

**Tech Stack:** C# (LangVersion `preview`, `Nullable` enable), .NET 11 SDK `11.0.100-preview.7.26381.103` pinned via `global.json`, xUnit v3 on Microsoft.Testing.Platform, Arcade build (`./build.sh`, `./test.sh`), SQL Server 2016+ for temporal functional tests.

**Spec:** `2026-08-14-temporal-entity-splitting-design.md` (rev 3.1, spike-validated) on this same orphan `specs` branch. Spike evidence: `2026-08-14-spike1-query-findings.md`, `2026-08-14-spike2-constraint-overrides-findings.md`, with the throwaway patches archived as `spike1.patch` / `spike2.patch`. **Read the spec before starting — this plan argues from it and does not restate its rationale.**

**Scope note:** Workstream A and Workstream B are independent subsystems shipping as separate upstream PRs; spec §7 states A has no implementation dependency on B. They are combined into one document at the author's request, but Phase B (Tasks B1–B10, presented first) and Phase A (Tasks A1–A14) are each independently shippable and each ends in a green build with tests. If you are executing only one workstream, execute one phase and ignore the other.

# Phase B — Workstream B: per-store-object key and FK constraint names

**Execute first.** See *Sequencing and PR mapping* above — the order is a preference, and the phases are independent.

Branch: `git switch -c feature/per-store-object-constraint-names main`

**What Spike 2 established, and what it did not.** The spike proved the *resolution* seams are exactly two functions and that the relational model consumes them untouched (5/5 green). What it explicitly shortcut — and what this phase must build properly — is the metadata family around them: typed override objects with configuration sources instead of raw `Dictionary` annotations, a convention-builder API instead of post-convention `OnModelCreating` writes, attach/merge survival, runtime-model conversion, snapshot codegen, and explicit-null semantics.

**The identity asymmetry is the crux.** Key overrides are keyed by a single `StoreObjectIdentifier` — a PK/AK constraint materializes once per table. FK constraint-name resolution is a **table-pair** relationship (`GetConstraintName(in StoreObjectIdentifier storeObject, in StoreObjectIdentifier principalStoreObject)`), and Spike 2 finding 1 confirmed why that matters: the entity-splitting linking constraint on every fragment maps to **one** self-referential model FK, so a single-store-object override could never name two fragments' linking constraints apart.

```csharp
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in

        => ((IReadOnlyStoreObjectDictionary<IReadOnlyRelationalKeyOverrides>?)key[RelationalAnnotationNames.KeyOverrides])
            ?.Find(storeObject);

    /// <summary>
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    public static RelationalKeyOverrides GetOrCreate(
        IMutableKey key,
        in StoreObjectIdentifier storeObject,
        ConfigurationSource configurationSource)
    {
        var keyOverrides = (StoreObjectDictionary<RelationalKeyOverrides>?)key[RelationalAnnotationNames.KeyOverrides];
        if (keyOverrides == null)
        {
            keyOverrides = new StoreObjectDictionary<RelationalKeyOverrides>();
            key[RelationalAnnotationNames.KeyOverrides] = keyOverrides;
        }

        var overrides = keyOverrides.Find(storeObject);
        if (overrides == null)
        {
            overrides = new RelationalKeyOverrides(key, storeObject, configurationSource);
            keyOverrides.Add(storeObject, overrides);
        }
        else
        {
            overrides.UpdateConfigurationSource(configurationSource);
        }

        return overrides;
    }
```

### Task B2: Key name resolution seam

Spike 2 finding: the two `(string?)key[RelationalAnnotationNames.Name] ?? defaultName` expressions in `RelationalKeyExtensions.GetName(key, storeObject, logger)` are the **entire** global-name fallback — a single seam in two branches. This task turns the spike's raw-dictionary lookup into a real one and pins the precedence.

Precedence, from most to least specific: **per-store-object override → global `Relational:Name` annotation → default generated name.** An override whose name is explicitly `null` suppresses down to the default name rather than falling through to the global annotation, because "I explicitly do not want the global rewritten name here" is exactly the NamingConventions #396 use case.

```csharp
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    public static bool IsTemporal(this ITable table)
    {
        if (table.FindRuntimeAnnotation(SqlServerAnnotationNames.IsTemporal) is { Value: bool cached })
        {
            return cached;
        }

        var storeObject = StoreObjectIdentifier.Table(table.Name, table.Schema);

        // Model validation has already established that every mapping agrees, so All() over the
        // mappings yields the single validated value with no canonical-mapping selection rule.
        var isTemporal = table.EntityTypeMappings.Any()
            && table.EntityTypeMappings.All(
                m => m.TypeBase is IEntityType entityType && entityType.IsTemporal(storeObject));

        table.SetRuntimeAnnotation(SqlServerAnnotationNames.IsTemporal, isTemporal);

        return isTemporal;
    }

    /// <summary>
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    public static IEntityType? FindTemporalEntityType(this ITable table)
    {
        if (!table.IsTemporal())
        {
            return null;
        }

        // Validation guarantees the history and period facets agree across every mapping on this
        // table, so any mapping carrying them answers for all of them. Root types are preferred
        // because period/history annotations live on the root in a TPH hierarchy.
        foreach (var mapping in table.EntityTypeMappings)
        {
            if (mapping.TypeBase is IEntityType entityType
                && entityType.IsTemporal()
                && entityType.GetPeriodStartPropertyName() != null)
            {
                return entityType;
            }
        }

        return null;
    }

    /// <summary>
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    public static IProperty? FindPeriodProperty(this ITable table, bool periodStart)
    {
        if (table.FindTemporalEntityType() is not { } entityType)
        {
            return null;
        }

        var periodPropertyName = periodStart
            ? entityType.GetPeriodStartPropertyName()
            : entityType.GetPeriodEndPropertyName();

        if (periodPropertyName == null)
        {
            return null;
        }

        // Locate the property through the table's column mappings rather than by enumerating
        // entity-type mappings, so the answer never depends on mapping order.
        foreach (var column in table.Columns)
        {
            foreach (var columnMapping in column.PropertyMappings)
            {
                if (columnMapping.Property.Name == periodPropertyName
                    && columnMapping.Property.DeclaringType == entityType)
                {
                    return columnMapping.Property;
                }
            }
        }

        return null;
    }
```

```csharp
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that

    protected virtual void ValidateTemporalMappingFragments(
        IEntityType entityType,
        IDiagnosticsLogger<DbLoggerCategory.Model.Validation> logger)
    {
        // Deliberately not guarded by entityType.IsTemporal(): ValidateTemporalTable early-returns for
        // non-temporal entity types, which would leave a fragment-level IsTemporal(true) unexamined.
        foreach (var fragment in entityType.GetMappingFragments())
        {
            var fragmentIsTemporal = fragment.IsTemporal();

            if (fragment.StoreObject.StoreObjectType != StoreObjectType.Table)
            {
                if (fragmentIsTemporal != null)
                {
                    throw new InvalidOperationException(
                        SqlServerStrings.TemporalNotSupportedForStoreObjectType(
                            entityType.DisplayName(), fragment.StoreObject.StoreObjectType));
                }

                continue;
            }

            if (!entityType.IsTemporal())
            {
                if (fragmentIsTemporal == true)
                {
                    throw new InvalidOperationException(
                        SqlServerStrings.TemporalFragmentOnNonTemporalEntityType(
                            entityType.DisplayName(), fragment.StoreObject.Name));
                }

                continue;
            }

            // The entity type is temporal, so every fragment must opt out explicitly. Both "absent"
            // (inherited temporality) and "true" land here; the error is lifted together when tier 2
            // adds real temporal-fragment support.
            if (fragmentIsTemporal != false)
            {
                throw new InvalidOperationException(
                    SqlServerStrings.TemporalSplitFragmentMustBeNonTemporal(
                        entityType.DisplayName(), fragment.StoreObject.Name));
            }

            ValidateTemporalPeriodPropertiesNotSplit(entityType, fragment);
        }
    }

    private static void ValidateTemporalPeriodPropertiesNotSplit(
        IEntityType entityType,
        IEntityTypeMappingFragment fragment)
    {
        // A period property carried into a fragment would leave the temporal root without period
        // columns, so reject it before the annotation provider ever sees the model.
        foreach (var periodPropertyName in new[]
                 {
                     entityType.GetPeriodStartPropertyName(), entityType.GetPeriodEndPropertyName()
                 })
        {
            if (periodPropertyName == null)
            {
                continue;
            }

            var periodProperty = entityType.FindProperty(periodPropertyName);
            if (periodProperty?.GetColumnName(fragment.StoreObject) != null)
            {
                throw new InvalidOperationException(
                    SqlServerStrings.TemporalPeriodPropertyMustBeMappedToPrincipalTable(
                        entityType.DisplayName(), periodPropertyName, fragment.StoreObject.Name));
            }
        }
    }
```

`GetColumnName(storeObject)` returns `null` for a property that is not mapped to that store object — for entity splitting it checks `property.FindOverrides(storeObject)`, which `SplitToTable(s => s.Property(...))` is what creates (`RelationalPropertyExtensions.cs:45–164`).
```csharp
    /// <summary>
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    protected virtual void ValidateTemporalTableSplitting(
        IReadOnlyList<IEntityType> mappedTypes,
        in StoreObjectIdentifier table,
        IDiagnosticsLogger<DbLoggerCategory.Model.Validation> logger)
    {
        if (table.StoreObjectType != StoreObjectType.Table)
        {
            return;
        }

        // (1) Every mapping must resolve to the same store-object temporal state. Unlike the previous
        // implementation this compares the *resolved* per-table value, so a non-temporal fragment of a
        // temporal entity type is correctly seen as non-temporal, and it runs even when a single root
        // type is involved.
        bool? expectedIsTemporal = null;
        foreach (var mappedType in mappedTypes)
        {
            var isTemporal = mappedType.IsTemporal(table);
            if (expectedIsTemporal == null)
            {
                expectedIsTemporal = isTemporal;
            }
            else if (expectedIsTemporal != isTemporal)
            {
                throw new InvalidOperationException(
                    SqlServerStrings.TemporalInconsistentTemporalStateForSharedTable(table.DisplayName()));
            }
        }

        if (expectedIsTemporal != true)
        {
            return;
        }

        // (2) History table name and schema must agree.
        var expectedHistoryTableName = default(string);
        var expectedHistoryTableSchema = default(string);
        var haveHistoryExpectation = false;

        // (3) Period column identity and hidden-state facets must agree.
        var expectedPeriodStartColumnName = default(string);
        var expectedPeriodEndColumnName = default(string);

        foreach (var mappedType in mappedTypes.Where(t => t.BaseType == null))
        {
            var historyTableName = mappedType.GetHistoryTableName();
            var historyTableSchema = mappedType.GetHistoryTableSchema();
            if (!haveHistoryExpectation)
            {
                expectedHistoryTableName = historyTableName;
                expectedHistoryTableSchema = historyTableSchema;
                haveHistoryExpectation = true;
            }
            else if (expectedHistoryTableName != historyTableName
                     || expectedHistoryTableSchema != historyTableSchema)
            {
                throw new InvalidOperationException(
                    SqlServerStrings.TemporalInconsistentHistoryTableForSharedTable(table.DisplayName()));
            }

            ValidatePeriodColumnConsensus(
                mappedType, table, periodStart: true, ref expectedPeriodStartColumnName);
            ValidatePeriodColumnConsensus(
                mappedType, table, periodStart: false, ref expectedPeriodEndColumnName);
        }
    }

    private static void ValidatePeriodColumnConsensus(
        IEntityType mappedType,
        in StoreObjectIdentifier table,
        bool periodStart,
        ref string? expectedColumnName)
    {
        var periodPropertyName = periodStart
            ? mappedType.GetPeriodStartPropertyName()
            : mappedType.GetPeriodEndPropertyName();

        if (periodPropertyName == null)
        {
            return;
        }

        var periodProperty = mappedType.FindProperty(periodPropertyName);

        // In the reverse-engineering scenario period properties are shadow-only and unmapped, in which
        // case the property name is the column name (see #26007).
        var columnName = periodProperty?.GetColumnName(table) ?? periodPropertyName;

        if (expectedColumnName == null)
        {
            expectedColumnName = columnName;
        }
        else if (expectedColumnName != columnName)
        {
            throw new InvalidOperationException(
                SqlServerStrings.TemporalNotSupportedForTableSplittingWithInconsistentPeriodMapping(
                    periodStart ? "start" : "end",
                    mappedType.DisplayName(),
                    periodPropertyName,
                    columnName,
                    expectedColumnName));
        }
    }
```

````markdown
# Splitting columns out of a populated temporal table

EF Core's migrations differ generates schema changes, never data movement. When you split
columns out of a table that already has rows, the generated migration will create the
fragment table and drop the columns — but nothing copies the existing values across, so
the drop destroys them.

Edit the scaffolded migration to insert a backfill between the two, in this order:

1. `CreateTable` for the fragment (generated).
2. **`migrationBuilder.Sql(...)` backfill (hand-authored — add this).**
3. `DropColumn` for each moved column on the principal table (generated).

```csharp
migrationBuilder.CreateTable(/* generated */);

migrationBuilder.Sql(
    """
    INSERT INTO [UserLockout] ([Id], [PasswordHash], [AccessFailedCount])
    SELECT [Id], [PasswordHash], [AccessFailedCount] FROM [Users];
    """);

migrationBuilder.DropColumn(name: "PasswordHash", table: "Users"); /* generated */
migrationBuilder.DropColumn(name: "AccessFailedCount", table: "Users"); /* generated */
```

Notes:

- One row per existing entity. `INSERT ... SELECT` over the principal table is the whole
  backfill; there is no history-side backfill, because the fragment is not temporal and
  has no history of its own.
- The generated `DropColumn` operations already wrap themselves in
  `SYSTEM_VERSIONING = OFF` / `ON` so the history table's copies of the columns are dropped
  too. Do not add your own wrapper.
- Write the `Down` migration symmetrically: re-add the columns, backfill back from the
  fragment, then drop the fragment table.
- **The moved columns' history is not migrated.** Values that existed in `UserHistory`
  before the split stay there in the dropped columns' place only if you copy them out
  first; by default they are gone. If the pre-split history of those columns matters,
  archive it before applying the migration.
````

### Task A11: Reject surviving fragment tables

Spec §3.4 step 4, validated by Spike 1. After pruning, walk the tree: for each table expression carrying a temporal-operation annotation, ban that entity's non-temporal fragment tables; if any banned table survived pruning, the query depends on fragment data and is rejected.

Two precision requirements from the spec, both easy to get wrong:

1. **"Temporal-annotated" means the table *expression* carries `TemporalOperationType`** — not that its `ITable` metadata is temporal. Otherwise ordinary current-time queries over temporal entities would be rejected.
2. **Correlation is by entity, not by table shape.** Resolve the stamped table's `ITableBase` → the entity types mapped to it → *those* entity types' non-temporal fragment tables. An unrelated explicit join to an ordinary table must be untouched.

Improving on the spike, the error names the offending **columns**, not just the table, by collecting column references against the surviving fragment's alias.

```csharp
// Licensed to the .NET Foundation under one or more agreements.
// The .NET Foundation licenses this file to you under the MIT license.

using Microsoft.EntityFrameworkCore.Query.SqlExpressions;
using Microsoft.EntityFrameworkCore.SqlServer.Internal;
using Microsoft.EntityFrameworkCore.SqlServer.Metadata.Internal;

namespace Microsoft.EntityFrameworkCore.SqlServer.Query.Internal;

/// <summary>
///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
///     the same compatibility standards as public APIs. It may be changed or removed without notice in
///     any release. You should only use it directly in your code with extreme caution and knowing that
///     doing so can result in application failures when updating to a new Entity Framework Core release.
/// </summary>
public sealed class SqlServerTemporalFragmentSurvivorVerifier : ExpressionVisitor
{
    private readonly List<TableExpression> _temporalTables = [];
    private readonly List<TableExpression> _allTables = [];
    private readonly Dictionary<string, SortedSet<string>> _referencedColumnsByAlias = new(StringComparer.Ordinal);

    /// <summary>
    ///     This is an internal API that supports the Entity Framework Core infrastructure and not subject to
    ///     the same compatibility standards as public APIs. It may be changed or removed without notice in
    ///     any release. You should only use it directly in your code with extreme caution and knowing that
    ///     doing so can result in application failures when updating to a new Entity Framework Core release.
    /// </summary>
    public static void Verify(Expression query)
    {
        var verifier = new SqlServerTemporalFragmentSurvivorVerifier();
        verifier.Visit(query);
        verifier.ThrowIfAnyFragmentSurvived();
    }

    /// <inheritdoc />
    protected override Expression VisitExtension(Expression node)
    {
        switch (node)
        {
            case TableExpression tableExpression:
                _allTables.Add(tableExpression);

                // A table *expression* carrying a temporal operation annotation — not an ITable whose
                // model metadata happens to be temporal. Ordinary current-time queries over temporal
                // entities carry no annotation and must not be rejected.
                if (tableExpression.FindAnnotation(SqlServerAnnotationNames.TemporalOperationType) is not null)
                {
                    _temporalTables.Add(tableExpression);
                }

                return node;

            case ColumnExpression columnExpression:
                if (!_referencedColumnsByAlias.TryGetValue(columnExpression.TableAlias, out var columns))
                {
                    columns = new SortedSet<string>(StringComparer.Ordinal);
                    _referencedColumnsByAlias[columnExpression.TableAlias] = columns;
                }

                columns.Add(columnExpression.Name);
                return node;

            case ShapedQueryExpression shapedQueryExpression:
                Visit(shapedQueryExpression.QueryExpression);
                return node;

            default:
                return base.VisitExtension(node);
        }
    }

    private void ThrowIfAnyFragmentSurvived()
    {
        if (_temporalTables.Count == 0)
        {
            return;
        }

        foreach (var temporalTable in _temporalTables)
        {
            // Correlation is by entity, not by table shape: only the fragments of the entity types
            // mapped to *this* temporal table are banned. Unrelated joins stay untouched.
            foreach (var mapping in temporalTable.Table.EntityTypeMappings)
            {
                if (mapping.TypeBase is not IEntityType entityType)
                {
                    continue;
                }

                foreach (var fragment in entityType.GetMappingFragments(StoreObjectType.Table))
                {
                    if (entityType.IsTemporal(fragment.StoreObject))
                    {
                        continue;
                    }

                    foreach (var survivor in _allTables)
                    {
                        if (survivor.Table.Name != fragment.StoreObject.Name
                            || survivor.Table.Schema != fragment.StoreObject.Schema)
                        {
                            continue;
                        }

                        var columns = _referencedColumnsByAlias.TryGetValue(survivor.Alias, out var referenced)
                            && referenced.Count > 0
                                ? "'" + string.Join("', '", referenced) + "'"
                                : "columns";

                        throw new InvalidOperationException(
                            SqlServerStrings.TemporalQueryDependsOnNonTemporalFragment(
                                entityType.DisplayName(),
                                columns,
                                fragment.StoreObject.Name,
                                temporalTable.Table.Name));
                    }
                }
            }
        }
    }
}
```

Two things to check when the tests in Task A12 run:

- If `ColumnExpression` instances reachable only through a join predicate cause false positives, note that the pruner has *already* run — a fragment table that only the join predicate references is removed before this verifier sees it (Spike 1 finding 1 confirmed join-predicate references correctly do not count). So a surviving fragment always has a real reference.
- `SortedSet<string>` gives a deterministic column list, which keeps the error message stable across runs and therefore assertable.
